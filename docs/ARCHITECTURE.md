# DetoxProxy — архитектура

## Главная идея

Внешней LLM не отдаются персональные данные — ни в каком виде. Не «модель попросили не разглашать», а модель их физически не получает: до отправки значения заменяются обратимыми токенами (`<<FIO_1>>`, `<<CARD_1>>`), которые сохраняют смысл задачи («у клиента карта `<<CARD_1>>`, PIN `<<PIN_1>>`»), а таблица соответствий остаётся только в памяти DetoxProxy. Ответ модели возвращается через тот же сервис и восстанавливается.

```
 система-потребитель                DetoxProxy                              внешняя LLM
 (CRM, чат-бот, …)      ┌─────────────────────────────────────┐
        │  текст с ПД   │ 1 детекция → 2 маскирование → 3 store│   текст без ПД
        ├──────────────►│   (spans)      (токены)     (payload_id)├──────────────►
        │               │                                     │
        │  ответ с ПД   │ 5 восстановление ◄── 4 поиск токенов │   ответ с токенами
        │◄──────────────┤                                     │◄──────────────┤
                        └─────────────────────────────────────┘
```

## Компоненты

| Модуль | Файл | Что делает |
|---|---|---|
| HTTP-сервер | `src/server` | axum + tokio; `/process`, `/v1/mask`, `/v1/unmask`, `/v1/detect`, `/healthz`, `/readyz`, `/metrics`; лимит одновременных запросов (семафор, дальше 429 с `Retry-After`), дедлайн на запрос, лимит размера тела |
| Реестр типов | `src/registry` | 17 типов ПД из `data/pii_types.yaml`: шаблоны, валидаторы, маркеры контекста, метки токенов, режим маскирования по умолчанию |
| Детектор | `src/detect` | находит спаны: регулярные выражения → валидаторы → словари → контекстные маркеры → оценка уверенности → разрешение пересечений |
| Маскирование | `src/mask` | заменяет спаны токенами / звёздочками / синтетикой / удаляет; восстановление по токенам |
| Хранилище соответствий | `src/store` | в памяти процесса (DashMap), TTL, лимит записей; ничего не пишется на диск |
| Конфигурация | `src/config` | системы-потребители и их политики; снапшот в `ArcSwap` (атомарная подмена) |
| Наблюдаемость | `src/obs` + сервер | JSON-логи без значений ПД, метрики Prometheus |

## Детекция: защита в глубину

Одно правило ошибается, несколько независимых сигналов — редко. Каждый кандидат проходит слои:

1. **Шаблон** — регулярное выражение формата (карта 4×4, ИНН 10/12 цифр, телефон, e-mail, даты, серия и номер паспорта…). Регистр не важен.
2. **Валидатор** — контрольная сумма ИНН и СНИЛС, Luhn для карт, календарная дата. Прошёл валидатор — высокая уверенность даже без контекста.
3. **Словари** — имена, фамилии, отчества, города, страны (открытые источники, см. `docs/LICENSES.md`); суффиксы фамилий и отчеств, падежные окончания.
4. **Контекст** — маркеры в окне вокруг значения: «паспорт», «ИНН», «проживает» повышают уверенность; «пример», «версия сборки», «отделение банка», «поэт», «в биографии» понижают. Решает **ближайшая** метка: в «CVV 317 и PIN 4821» число 4821 — PIN, а не CVV.
5. **Ловушки** — общеизвестные персоны из allowlist без признаков клиента, исторические даты, топонимы-омонимы фамилий («г. Пушкин»), адреса организаций, названия полей без значений.
6. **Разрешение пересечений** — длиннее, затем увереннее.
7. **Политика системы** — порог уверенности, набор типов, `trap_policy` (что делать со спорным случаем), правило комбинаций (PIN/CVV только рядом с картой).

Модели машинного обучения нет — это осознанный выбор: предсказуемая задержка (миллисекунды на типичный запрос, без GPU), объяснимость каждого решения, настройка данными без переобучения.

## Токены

- Формат `<<LABEL_N>>`, метки короткие: `FIO`, `BDATE`, `PASSPORT`, `PASSISS`, `DRIVLIC`, `CARDHLD`…
- Одинаковое значение в одном запросе — один токен; разные — разные номера.
- Режим `hash`: `<<INN_f5c0b7>>` — хеш значения с солью системы. Одинаковое значение даёт одинаковый токен между запросами — префикс промпта не меняется, кеш промптов LLM не ломается; соль у каждой системы своя, поэтому токены двух систем несопоставимы.
- Восстановление терпимо к искажениям модели: регистр и пробелы внутри (`<< inn_1 >>`).

## Жизненный цикл данных (152-ФЗ: минимизация)

- Исходные значения живут только в памяти процесса, в записи под `payload_id` / `session_id`, с TTL (по умолчанию 15 минут) и лимитом числа записей.
- На диск, в логи, в метрики, в тексты ошибок значения не попадают — это проверяется тестами (`check_process.py`: нет ПД в `/metrics` и в логе сервиса).
- Повтор запроса с тем же `payload_id` и исходным текстом возвращает ту же маску, а не маскирует заново; маска, пришедшая с тем же `payload_id`, восстанавливается.
- Это псевдонимизация, а не анонимизация: у DetoxProxy есть ключ обратного преобразования, у LLM — нет.

## Производительность

- Rust, один статический бинарник, аллокатор mimalloc, `TCP_NODELAY`.
- Регулярные выражения компилируются один раз при старте; конфигурация берётся атомарным снапшотом без блокировок.
- Хранилище — шардированная хеш-таблица (DashMap), без глобальной блокировки.
- Перегрузка — быстрый отказ 429 с `Retry-After`, а не рост очереди и таймауты.

Цифры нагрузочного прогона — `docs/LOAD.md`.

## Конфигурация и расширение

- Новый тип ПД — запись в `data/pii_types.yaml` (шаблон, валидатор, маркеры, метка токена), без правки кода детектора.
- Новая система-потребитель — блок в `config.yaml`: свои типы, режимы маскирования по типам, порог, политика ловушек, нумерация токенов, соль.
- Подробно — раздел «Настройка» в `README.md`.
