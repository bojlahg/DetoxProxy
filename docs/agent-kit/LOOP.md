# LOOP — цикл «Claude пишет ТЗ → DeepSeek исполняет → Claude проверяет»

Проверено 21.09.2026 на трёх полных задачах и одном раунде ревью. Запускалка: `bakeoff/agent.sh` (на хакатоне скопировать в `tools/agent.sh` основного репозитория).

## Запуск

```bash
tools/agent.sh <папка> <файл_ТЗ.md | "текст"> --accept "<команда приёмки>" --protect "<файлы, которые агенту менять нельзя>"
```

Долгие задачи запускать в фоне (`run_in_background`), уведомление придёт по завершении. Итог — одна строка `VERDICT=...` и запись в `logs/runs.jsonl`.

| VERDICT | Значение | Действие |
|---|---|---|
| `PASS` | агент завершился сам, независимая приёмка зелёная | ревью диффа, коммит |
| `ACCEPT_FAILED` | агент отчитался, но приёмка красная | новая сессия с уточнённым ТЗ и текстом ошибки приёмки |
| `AGENT_FAILED` | агент упал, завис (лог не рос 8 мин) или вышел по общему таймауту | смотреть `logs/<имя>-N.err`, перезапуск |
| `PASS_AGENT_INTERRUPTED` | агент прерван сторожком, но приёмка зелёная | проверить, что работа доделана, а не брошена на середине |
| `PROTECTED_FILE_CHANGED` | агент изменил защищённый файл (тесты, приёмку) | откатить файл, перезапуск с явным запретом |
| `AGENT_COMMITTED` | агент сделал коммит (HEAD сдвинулся), хотя это запрещено | `git reset --soft` к прежнему HEAD, проверить содержимое, закоммитить самому после ревью |
| `DONE_UNVERIFIED` | приёмка не задана | так не запускать: приёмка обязательна |

## Claude код не пишет

Правило пользователя (22.09): оркестратор не пишет и не правит код продукта — ни модули, ни тесты, ни мелкие правки. Всё через ТЗ и замечания ревью агенту. Формат замечания — как `bakeoff/go/REVIEW-1.md`: для каждого пункта файл, функция, что не так, требуемое поведение; в конце команда приёмки и правило «меняй только названные файлы». ## Кто коммитит

Коммитит ревьюер (Claude), агент — никогда. Коммит = проверенное состояние: одна задача → `VERDICT=PASS` → ревью диффа → один коммит. Каждый коммит — точка, к которой безопасно откатиться.

Защита в два слоя, обе проверены 22.09:
1. `opencode.json` в корне репозитория (шаблон — `docs/agent-kit/opencode.json`): команды `git add/commit/push/reset/checkout/restore/stash/rebase/merge/clean/tag` запрещены правилом, `--auto` этот запрет не снимает. Тот же файл закрепляет модель `alfagen/...` по умолчанию, в том числе для служебных запросов.
2. `agent.sh` сравнивает HEAD до и после агента; сдвиг даёт `AGENT_COMMITTED` (обход шаблона вроде `git -C . commit` ловится здесь).

Порядок после задачи:
1. `VERDICT=PASS` получен в этом же ходе.
2. `git status --short` и `git diff --stat`: изменены только файлы из `files_allowed` задачи; нет бинарников, `target/`, логов, секретов.
3. Дифф прочитан, требования ТЗ найдены в коде.
4. `git add <конкретные файлы>` (не `git add -A`), коммит с сообщением на английском `T07: <what was done>`.
5. При `ACCEPT_FAILED` или плохом диффе: `git stash -u` либо `git checkout -- . && git clean -fd <папка задачи>` к последнему зелёному коммиту, затем новая сессия с уточнённым ТЗ. Перед удалением посмотреть, что именно удаляется.

Сообщения коммитов — на английском, в повелительном наклонении, с идентификатором задачи: `T07: add retry with full jitter and fallback chain`. В теле — результат приёмки (`Acceptance: check.py 10/10, clippy clean`).

Подписи: строку `Co-Authored-By: Claude ...` в коммиты НЕ добавлять (решение пользователя от 22.09, чтобы не вызывать вопросов у жюри). В коммитах с кодом, написанным агентом, допустима строка `Generated-by: DeepSeek-V4-Flash-0731 (AlfaGen, OpenCode)`; в коммитах с документами её не ставить — это было бы неправдой.

## Языки

Документы, ТЗ, отчёты — на русском. В коде только английский: идентификаторы, комментарии, сообщения логов и ошибок, имена метрик и тестов, ключи конфигурации. Кириллица в исходниках — только в тестовых данных. При ревью диффа это отдельный пункт проверки: `LC_ALL=C.UTF-8 grep -nP "[А-Яа-яЁё]" <изменённые файлы кода>` не должен находить ничего вне тестовых данных.

## Известные ловушки (каждая стоила времени 21.09)

1. **`opencode run` с открытым stdin зависает молча** — ждёт ввод. Всегда `< /dev/null`. В `agent.sh` это учтено; вручную `opencode run` без этого не запускать.
2. **Флаги `--variant` и `--thinking` с провайдером alfagen дают пустой вывод.** Не использовать.
3. **`cargo` нет в PATH сессии** до перезапуска приложения — `agent.sh` добавляет путь сам.
4. **Относительный путь к бинарнику с подкаталогом** (`target/release/proxy.exe`) Windows не запускает — в приёмке приводить к абсолютному.
5. **Детектор гонок Go (`-race`) недоступен** на Windows без gcc. Не требовать его в приёмке.
6. **Русский текст в JSON-логе OpenCode отображается кракозябрами** — это только вывод в лог, модель получает корректный UTF-8.
7. **Kilo Code после добавления провайдера остаётся на `kilo-auto/free`.** Проверять по логу: `providerID=alfagen`.
8. **`taskkill` принимает Windows-PID**, а не PID из bash: брать из `/proc/<pid>/winpid`.

## Правила проверки на стороне Claude

Отчёт агента — не доказательство. Перед словом «сделано» обязательно:

1. **Приёмка запущена мной**, а не агентом, и я видел её вывод в этом же ходе (`VERDICT=PASS` либо `ИТОГ: N/N`).
2. **Дифф прочитан**: каждое требование ТЗ найдено в коде глазами, а не только поиском по ключевым словам. Поиск — первый фильтр, чтение — подтверждение.
3. **Защищённые файлы не тронуты** (контрольные суммы сверяет `agent.sh`).
4. **Провайдер и модель верные**: в `runs.jsonl` есть `session`, при сомнении — `opencode export <session>` и проверка `providerID`.
5. **Фоновые процессы**: после запуска проверить, что лог растёт; после завершения — что не осталось процессов агента и занятых портов.
6. **Сторожок есть у всего, что может зависнуть**: агент, приёмка, нагрузочный тест — только через `timeout` или `agent.sh`.
7. Если что-то не проверено — так и писать: «не проверено», с причиной. Не писать «работает» по косвенным признакам.

## Учёт времени

Каждый запуск `agent.sh` помечается задачей (`--task T04`, иначе имя файла ТЗ) и пишет секунды и шаги в `logs/runs.jsonl`. Сводка: `python tools/timing.py`. Пороги и действия при превышении — `CLAUDE.md`, раздел «Учёт времени и смена тактики»: задача блока 1 дольше 20 мин или больше 2 раундов → разбить ТЗ; блок 2–3 дольше 40 мин или 3 раундов → то же, при повторе пересмотреть план; 2 ч без зелёных T01–T04 → переход на Go. О превышении сначала сообщить пользователю.

Конкретные правки («в `attempt()` замени X на Y», вплоть до фрагмента кода) в ТЗ и замечаниях давать можно — вносит их агент.

## Размер задач

По опыту 21.09: задача на 200–250 строк кода закрывается за 1,5–3 минуты и 8–11 тыс. выходных токенов; раунд ревью из трёх замечаний — 3,3 минуты. Модель работает без thinking, поэтому: одна задача — одна сессия, ТЗ с явным планом и исполняемой приёмкой, замечания ревью — с указанием файла, функции и требуемого решения.
