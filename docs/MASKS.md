# Режимы маскирования

Что именно подставляется вместо найденного значения, решает политика системы-потребителя (`X-System-Id` → блок `systems` в `config.yaml`). Один и тот же текст в разных режимах:

> Клиент Сидоров Пётр Иванович, паспорт 4509 123456, ИНН 500100732259, тел. +7 912 345-67-89, проживает: г. Казань, ул. Баумана, д. 14, кв. 8.

| Режим | Результат | Обратимо |
|---|---|---|
| `token` | Клиент `<<FIO_1>>`, паспорт `<<PASSPORT_1>>`, ИНН `<<INN_1>>`, тел. `<<PHONE_1>>`, проживает: `<<ADDR_1>>`. | да, всегда |
| `pseudonym` | Клиент Черняков Ираклий Ильич, паспорт 0916 328299, ИНН 175935253971, тел. +7 989 602-80-51, проживает: г. Глазов, ул. Полевая, д. 12, кв. 5. | да, пока подстановка не изменена |
| `stars` | Клиент С. П. И., паспорт 45\*\* \*\*\*\*56, ИНН \*\*\*\*\*\*\*\*\*\*\*\*, тел. +7 \*\*\* \*\*\*-\*\*-89, … | да, пока маска уникальна в тексте |
| `synthetic` | случайные значения того же формата, без согласования между собой | да, пока подстановка не изменена |
| `remove` | Клиент [removed], паспорт [removed], … | **нет**, по замыслу |
| `off` | тип не маскируется | — |

## Когда какой

- **`token`** — по умолчанию и для LLM. Модель видит явный заполнитель, не пытается его «исправить», а восстановление не зависит от того, как модель переписала текст вокруг. Устойчиво к искажениям: `<< inn_1 >>`, `<<Inn_1>>` восстанавливаются так же.
- **`pseudonym`** — когда текст должен остаться естественным: обучающие выборки, демо, отчёты, которые читает человек, или модель, которая на `<<FIO_1>>` начинает писать хуже. Подстановки правдоподобны:
  - ФИО той же формы: пол, падеж и группа фамилии сохраняются («Сидорову Петру Ивановичу» → «Чернякову Ираклию Ильичу»), регистр тоже («ИВАНОВ ИВАН ИВАНОВИЧ» → «СИЗОВ АЛЕКСЕЙ ИЛЬИЧ»);
  - ИНН, СНИЛС и номер карты проходят свои контрольные суммы, ИНН не начинается с нуля, карта начинается с 2, 4 или 5 (Мир, Visa, Mastercard);
  - адрес заменяется по частям: другой город, другая улица, другие номера дома и квартиры, маркеры «г.», «ул.», «д.», «кв.» на месте;
  - одно и то же значение в тексте получает одну и ту же подстановку, подстановка никогда не совпадает с другим значением из того же текста.
- **`stars`** — для логов и интерфейсов, где человеку нужно узнать запись, но не прочитать её: у карты видны первые и последние 4 цифры, у телефона — последние 2, у email — домен, ФИО — инициалы. Сколько символов оставить, задаётся на тип в `data/pii_types.yaml` (`stars_keep_prefix`, `stars_keep_suffix`).
- **`synthetic`** — упрощённый вариант `pseudonym` без согласования падежа и пола. Оставлен для совместимости; для новых систем лучше `pseudonym`.
- **`remove`** — когда значение не должно вернуться никогда: выгрузки наружу, аналитика. `unmask` оставляет `[removed]` как есть.

## Где задаётся

Три уровня, более частный побеждает:

```yaml
systems:
  - id: support
    mask_mode: pseudonym          # 3. режим системы для всех типов
    overrides:
      card_number: stars          # 1. режим типа внутри системы
      cvv: remove
```

```yaml
# data/pii_types.yaml
  - id: card_pin
    mask: remove                  # 2. режим типа по умолчанию во всех системах
```

## Нумерация токенов

`token_numbering` у системы:

- `sequential` — `<<INN_1>>`, `<<INN_2>>` в порядке появления, счёт свой в каждом запросе;
- `hash` — `<<INN_f5c0b7>>`: первые 6 символов SHA-256 от соли системы (`hash_salt`) и нормализованного значения. Один и тот же ИНН даёт один и тот же токен во всех запросах этой системы — не ломается кеш промптов LLM, и модель видит, что в двух сообщениях речь об одном человеке. Соль у каждой системы своя, поэтому токены разных систем не сопоставить.

В `pseudonym` с `hash` имена и города тоже стабильны между запросами; цифровые значения генерируются заново.

## Падежи при восстановлении

Токен можно дополнить падежом: `<<FIO_1:дат>>`, `<<FIO_1:им>>`. Допустимы `им`, `род`, `дат`, `вин`, `тв`/`твор`, `пр`/`предл` и английские `nom`, `gen`, `dat`, `acc`, `ins`, `prep`. При восстановлении ФИО, город, страна или улица ставятся в нужную форму:

```
«Уважаемый <<FIO_1:им>>»   → «Уважаемый Иванов Иван Иванович»
«Передайте <<FIO_1:дат>>»  → «Передайте Иванову Ивану Ивановичу»
```

LLM-прокси (`/v1/chat/completions`) сам добавляет модели инструкцию про эти суффиксы (`llm.case_hints`, включено по умолчанию). Без суффикса значение восстанавливается в том виде, в каком было в исходном тексте.

## Ограничения

- `pseudonym`, `synthetic`, `stars` восстанавливаются поиском точной подстановки. Если модель склонила подставленную фамилию («Чернякова» вместо «Черняков»), восстановится только несклонённое вхождение. Для LLM поэтому основной режим — `token`.
- `stars` у коротких значений может дать одинаковую маску для разных значений (два PIN-кода → `****`). Восстановится первое. Для обратимости с короткими типами — `token`.
