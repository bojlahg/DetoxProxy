# Маскирование vs токенизация vs synthetic replacement

## Определения

```
Иван Иванов → ***********        # masking (необратимое в потоке)
Иван Иванов → {PERSON_1}         # tokenization (обратимое через state)
Иван Иванов → Пётр Петров        # synthetic replacement (суррогат)
```

## Сравнение

| Критерий | Masking (`***`, `█`) | Tokenization `{TYPE_N}` | Synthetic (Пётр Петров) |
|---|---|---|---|
| Качество prompt для LLM | низкое (теряется грамматика/род/падеж) | высокое (тип сохранён, структура видна) | высокое (естественный текст) |
| Восстановимость (демаскирование) | нет (только если хранить отдельно) | да (map token→value, per-request state) | да, но нужен map оригинал→суррогат |
| Безопасность | высокая (утечке нечего) | средняя (state — цель атаки; token enumeration) | средняя (суррогат может коллизить с реальным лицом!) |
| Производительность | O(n), stateless | O(n) + HashMap lookup, state per request | O(n) + словарь/генератор, риск коллизий |
| State | не нужен | нужен (TTL, изоляция между запросами/тенантами) | нужен (консистентность в рамках запроса) |
| Collision risks | нет | низкие (`{PERSON_1}` уникален в запросе) | высокие (Пётр Петров может быть реальным клиентом!) |
| Удобство для LLM | плохое (модель «слепнет») | хорошее (типизированные токены) | лучшее (естественность), но вводит в заблуждение |

## Typed tokens (рекомендация)

```
{PERSON_1}, {PHONE_1}, {PASSPORT_1}, {CARD_1}, {ADDRESS_1}, {INN_1}, ...
```

- Стабильность в рамках запроса: `Иван позвонил Ивану → {PERSON_1} позвонил {PERSON_1}` (канонизация по нормализованному значению: нижний регистр, strip сепараторов, NFC).
- Счётчики per-type per-request (`PERSON_1, PERSON_2...`), не глобальные (иначе утечка кросс-запросов).
- Формат токена должен быть невозможен в нормальном тексте (`{...}` + редкий префикс, напр. `__PII_PERSON_1__`), чтобы LLM не галлюцинировал такие же и демаскирование было однозначным.
- Демаскирование: применять к ответу LLM маппингом справа-налево; нетокенизированные галлюцинации модели (`{PERSON_99}`) — не раскрывать, логировать.

## Безопасность state

- Хранить только в памяти запроса (request-scoped), TTL секунды–минуты, zeroize после ответа.
- Не логировать raw values; логи — только типы и counts.
- Шифрование state при выносе за процесс (Redis) — AES-GCM с per-request ключом.

Источник идей: Presidio Anonymizer/Deanonymizer (mask/redact/replace/hash/encrypt operators), pii.engineer (auto-redaction в одном вызове).
