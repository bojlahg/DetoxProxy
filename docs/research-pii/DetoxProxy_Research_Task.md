# ТЗ: Research Pack для DetoxProxy

## 0. Контекст

Проект создаётся для хакатона Alfa Vibe Coding.

Задача: высоконагруженный модуль защиты персональных данных в цепочке:

```text
Система-потребитель
        ↓
    DetoxProxy
        ↓
идентификация ПД
        ↓
маскирование / токенизация
        ↓
       LLM
        ↓
демаскирование
        ↓
Система-потребитель
```

Основные требования хакатона:

- распознавание персональных данных;
- маскирование;
- демаскирование;
- качество около 95%+;
- основной язык: русский;
- до 100 000 токенов во входном тексте;
- 1000 RPS;
- целевой latency ≤ 1 с;
- желательно 2000 RPS;
- в критериях жюри ориентир для сильного решения: ≤ 0.5 с;
- ложные срабатывания должны быть минимальными;
- общеизвестные сведения не должны считаться ПД;
- пример hard negative: Александр Сергеевич Пушкин;
- адрес офиса/отделения банка также не должен автоматически считаться ПД.

Основной проект предположительно будет написан на Rust.

---

## 1. Цель работы

Не разрабатывать основной сервис.

Не принимать архитектурных решений вместо основного архитектора.

Твоя задача — собрать и структурировать исследовательские материалы, которые помогут быстро реализовать качественное PII detection/masking решение.

На выходе должна получиться отдельная папка с:

1. внешними датасетами;
2. benchmark-наборами;
3. примерами;
4. сведениями о существующих библиотеках;
5. алгоритмами проверки российских идентификаторов;
6. нормативной справкой;
7. анализом существующих open-source решений;
8. готовым тестовым corpus для дальнейшей разработки DetoxProxy.

## 21. Маскирование vs tokenization vs synthetic replacement

Исследовать три подхода.

### Masking

```text
Иван Иванов
→ ***********
```

### Tokenization

```text
Иван Иванов
→ {PERSON_1}
```

### Synthetic replacement

```text
Иван Иванов
→ Пётр Петров
```

Для каждого описать:

- влияние на качество prompt;
- возможность восстановления;
- безопасность;
- производительность;
- необходимость state;
- collision risks;
- удобство для LLM.

Отдельно рассмотреть typed tokens:

```text
{PERSON_1}
{PHONE_1}
{PASSPORT_1}
{CARD_1}
```

и стабильность одинакового значения внутри одного запроса:

```text
Иван позвонил Ивану
→
{PERSON_1} позвонил {PERSON_1}
```

- делать web UI;

## 31. Git

Если рабочая папка является Git-репозиторием:

Перед началом:

```text
git status
git pull --rebase
```

Не добавлять datasets/models/binaries в Git.

После завершения добавить только:

```text
*.md
scripts
небольшие metadata
небольшие synthetic corpus
```

Сделать один осмысленный commit.

В конце вывести:

```text
git status
```

и перечислить созданные файлы.

## 32. Главное ограничение

Это исследовательская задача.

Если во время работы обнаружится идея, которая может серьёзно изменить архитектуру DetoxProxy, НЕ реализовывать её самостоятельно.

```text
REPORT.md → Architectural findings

проблема
варианты

```
