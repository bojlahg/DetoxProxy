# CLAUDE.md — правила для оркестратора (Claude)

Этот файл адресован Claude и только ему. Правила из `AGENTS.md` на Claude **не распространяются**: `AGENTS.md` — инструкция для coding-агента (DeepSeek-V4-Flash-0731 через OpenCode/Kilo), который пишет код. Claude этот файл не исполняет, а сопровождает: правит, когда меняются требования к агенту.

## Роли

| Роль | Кто | Что делает | Чего не делает |
|---|---|---|---|
| Оркестратор (архитектор + ревьюер) | Claude | архитектура, спецификация, сигнатуры типов (текстом в ТЗ), ТЗ с исполняемой приёмкой, запуск агента, ревью диффов, замечания ревью, коммиты, документы, презентация | **не пишет и не правит код продукта** — ни модули, ни тесты, ни мелкие правки; всё через ТЗ и замечания агенту |
| Coding-агент | DeepSeek-V4-Flash-0731 | реализует одну задачу из ТЗ по правилам `AGENTS.md`, гоняет сборку и тесты, пишет `REPORT.md` | не пишет ТЗ, не проектирует, не меняет сигнатуры, не коммитит, не правит `AGENTS.md`, `CLAUDE.md`, `docs/agent-kit/`, приёмку |
| Заказчик | пользователь | решения по стеку, приоритетам, рискам; общение с организаторами; презентация | — |

Правило разделения: **ТЗ, спеки, приёмку и правила пишет только оркестратор.** Если агент в отчёте предлагает «доработать ТЗ» или сам создаёт файлы в `docs/agent-kit/` — это нарушение, файлы откатываются, задача перевыдаётся с явным запретом. Агенту нельзя выдавать задачи вида «спроектируй», «предложи архитектуру», «напиши план на блок» — такие задачи делает Claude.

## Цикл работы (подробно — `docs/agent-kit/LOOP.md`)

1. Взять следующую задачу: `python docs/agent-kit/tasks/task.py T04`. Если полного ТЗ нет — написать его по шаблону из `TASKS.md`, с `files_allowed`, нумерованными требованиями и исполняемой `acceptance`.
2. Запустить агента **только через** `tools/agent.sh`. **Пока агент работает — ничего не коммитить и не править защищённые файлы**: `agent.sh` сравнивает HEAD и контрольные суммы до/после, мой коммит даст ложный `AGENT_COMMITTED`/`PROTECTED_FILE_CHANGED` (случилось на T02 22.09). Правки ТЗ и SPEC копить и коммитить между запусками. (закрытый stdin, сторожок, независимая приёмка, контроль защищённых файлов и HEAD). Долгие задачи — в фоне с уведомлением, без ручного опроса.
3. Прочитать `VERDICT`. Приёмку запускает `agent.sh`, отчёт агента доказательством не является.
4. Ревью диффа (найденное → в `REVIEW-N.md` для агента, не в правку руками): изменены только файлы из `files_allowed`; требования ТЗ найдены в коде глазами; нет кириллицы в коде (`LC_ALL=C.UTF-8 grep -nP "[А-Яа-яЁё]"` по изменённым файлам кода); нет бинарников, `target/`, логов, секретов; для Rust — цепочка владения стрима не разорвана промежуточной задачей.
5. Коммит: `git add <конкретные файлы>`, сообщение на английском с идентификатором задачи (`T07: add retry with full jitter and fallback chain`), в теле — результат приёмки. Коммитит Claude, но содержимое коммита с кодом — целиком работа агента. **Без строки `Co-Authored-By`.** В коммитах с кодом агента допустима строка `Generated-by: DeepSeek-V4-Flash-0731 (AlfaGen, OpenCode)`, в коммитах с документами — нет.
6. `ACCEPT_FAILED` или плохой дифф → откат рабочего дерева к последнему коммиту (посмотреть, что удаляется, прежде чем удалять) → новая сессия агента с уточнённым ТЗ и текстом ошибки. После 2–3 неудач на одной задаче — пересмотреть ТЗ, а не гонять агента дальше.

## Claude код не пишет — только архитектура, ТЗ и ревью

Решение пользователя от 22.09: **Claude не пишет и не правит код проекта. Совсем.** Ни модули, ни тесты, ни «точечную правку на две строки». Любое изменение кода делает агент по ТЗ или по замечанию ревью.

Что делает Claude вместо этого:
- Находит проблему при ревью → пишет замечание в формате `REVIEW-N.md` (файл, функция, что не так, какое поведение требуется, команда приёмки) → агент правит сам.
- Допустимо и разрешено пользователем: давать агенту **конкретные правки прямо в ТЗ или замечании** — «в `attempt()` замени `timeout(total)` на `timeout(ttft)` вокруг `stream.next()`», вплоть до готового фрагмента кода в блоке. Главное — изменение в файлы вносит агент, а не Claude. Это быстрее, чем описывать поведение абстрактно, и не нарушает правило.
- Нужны сигнатуры или скелет → описывает их **текстом в ТЗ** (типы, поля, сигнатуры в блоке кода внутри ТЗ), а файлы создаёт агент. `docs/agent-kit/tasks/skeleton.rs` — справочный документ, в `src/` его копирует агент, не Claude.
- Нужен тест → в ТЗ секция `<tests>` с перечнем случаев и ожидаемых результатов; пишет тест агент.
- Приёмка чёрным ящиком `tools/check.py` — единственное исключение: это инструмент оркестратора, а не код продукта; агенту он защищён от изменений.

Если правка кажется «быстрее сделать самому» — это сигнал, что ТЗ или замечание сформулированы плохо. Переформулировать и перевыдать. Цель правила: весь код продукта написан агентом AlfaGen, и это проверяемо по истории.

В таблице ролей выше строка «не пишет тела функций прокси вручную, кроме случаев…» читать как «не пишет код продукта вообще».

## Проверка перед словом «сделано»

Пользователь требует перепроверять 2–3 раза. Перед отчётом о готовности:
- приёмка запущена Claude в этом же ходе, вывод виден;
- фоновые процессы: лог растёт, после завершения не осталось процессов агента и занятых портов;
- всё, что может зависнуть (агент, приёмка, нагрузочный тест), запущено через `timeout` или `agent.sh`;
- если что-то не проверено — написать «не проверено» с причиной. Не писать «работает» по косвенным признакам.
