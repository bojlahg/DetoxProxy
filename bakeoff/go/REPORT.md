# REPORT

## Что сделано
Написан HTTP-прокси для OpenAI-совместимого LLM API на Go (только stdlib, `net/http`).

- **Конфигурация** через переменные окружения: `LISTEN_ADDR`, `UPSTREAMS`, `TTFT_TIMEOUT_MS`.
- **Эндпоинты**: `GET /healthz` → 200; `GET /metrics` → Prometheus-текст со счётчиком `proxy_requests_total`; `POST /v1/chat/completions` → проксирование на upstream.
- **Проброс**: тело запроса и заголовок `Authorization` передаются upstream без изменений.
- **Стриминг (SSE)**: каждое событие пересылается клиенту немедленно с `Flush()` (задержка единицы мс).
- **Отмена при отключении клиента**: по `r.Context().Done()` закрывается соединение с upstream.
- **Failover до первого байта**: при 5xx/429, ошибке подключения или превышении `TTFT_TIMEOUT_MS` (до первого события тела, а не до заголовков) запрос повторяется на следующем upstream; зависшая попытка отменяется.
- **Retry после первого байта запрещён**: после отправки первого байта клиенту стрим просто завершается при обрыве upstream.
- **Нагрузка**: выдерживает 200 одновременных стримов без потерь событий.

## Проблемы
- Первая сборка не находила модуль (не было `go.mod`) — создан `go mod init proxy`.
- Реализация failover для стриминга требует буферизации заголовков upstream до получения первого события тела, чтобы не отправлять клиенту байты до коммита; это учтено в `tryUpstream`.

## Раунд ревью 1

Исправлены замечания из REVIEW-1.md (только `main.go`):

- **R1 (пул соединений)**: вместо создания нового `http.Client` с `DisableKeepAlives: true` на каждый запрос введён один общий `client` на процесс. `Transport` настроен: `MaxIdleConns=1024`, `MaxIdleConnsPerHost=512`, `IdleConnTimeout=90s`, `DisableCompression=true`, `DialContext` с таймаутом подключения 2s, keep-alive включён. Для каждой попытки создаётся дочерний `context.WithCancel` от `r.Context()`, `cancel()` вызывается при выходе из попытки (включая TTFT-таймаут), что закрывает соединение с upstream при отмене.
- **R2 (гонка данных в streamRest)**: goroutine, писавшая в `ResponseWriter`, убрана. Чтение upstream и запись клиенту выполняются в одном цикле в goroutine обработчика; отмена обеспечивается контекстом. Ожидание первого чанка больше не пишет в `ResponseWriter` из goroutine: после TTFT-таймаута контекст попытки отменяется и goroutine чтения дожидается через канал перед возвратом.
- **R3 (лимит тела)**: тело читается через `http.MaxBytesReader` с лимитом 10 MB; при ошибке чтения — 400 с JSON-ошибкой, при превышении лимита — 413.

Результат проверки: `go build -o proxy.exe . && go vet ./...` — чисто; `python check.py --cmd "./proxy.exe" --base-port 18100` — `ИТОГ: 10/10`.
