# REPORT

## Что сделано

Написан HTTP-прокси для LLM API (OpenAI-совместимый, со стримингом SSE) на чистом C11
(только libc + pthread-независимый однопоточный epoll-цикл, без внешних библиотек).

Реализовано:
- Конфигурация через переменные окружения `LISTEN_ADDR`, `UPSTREAMS`, `TTFT_TIMEOUT_MS`.
- Эндпоинты: `GET /healthz` → 200, `GET /metrics` → Prometheus-текст со счётчиком
  `proxy_requests_total`, `POST /v1/chat/completions` → проксирование на upstream.
- Тело запроса и заголовок `Authorization` передаются upstream без изменений (сырые байты).
- Стриминг SSE: каждое событие пересылается клиенту немедленно (без буферизации, с flush).
- Failover до первого байта клиенту: при 5xx/429, ошибке подключения или таймауте первого
  SSE-события (TTFT) запрос повторяется на следующем upstream; зависшая попытка отменяется.
- После первого байта клиенту retry запрещён; обрыв upstream посреди стрима корректно
  завершает клиентский стрим.
- При закрытии клиентом соединения посреди стрима прокси немедленно закрывает соединение
  с upstream.
- Если все upstream отказали — ответ 502/503 с JSON-телом `{"error": {...}}`.
- Держит 200+ одновременных стримов без потерь событий.

## Итерации проверки

Понадобилось 3 итерации до полного зелёного результата.

## Проблемы и их решение

1. **Upstream-сокет не был зарегистрирован в таблице соединений.**
   Сокет upstream добавлялся в epoll, но не в массив `g_conns`, поэтому события
   `EPOLLOUT`/`EPOLLIN` для него отбрасывались (`conn_get(fd)` возвращал NULL) — запросы
   зависали. Исправлено: upstream-fd регистрируется в `g_conns` при `start_connect`,
   а при закрытии очищается в `close_upstream`/`close_conn`.

2. **Порядок объявлений в C.** `Conn` использовался в глобалах до определения структуры —
   добавлен forward-declaration и перенесены глобальные переменные после определения.

3. **Предупреждения компилятора.** Убраны неиспользуемые переменные, добавлены
   forward-declarations функций — сборка чистая с `-Wall -Wextra`.

## Результат

- Обычная сборка (`make`): `ИТОГ: 10/10`.
- ASan-сборка (`make asan`, `--skip-load`): `ИТОГ: 9/9`, отчётов AddressSanitizer в
  `proxy.log` нет.
