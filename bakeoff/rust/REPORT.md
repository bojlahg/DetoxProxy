# REPORT

## Что сделано

Написан HTTP-прокси для OpenAI-совместимого LLM API на Rust (axum 0.8 + reqwest 0.13).

Функциональность:
- `GET /healthz` → 200
- `GET /metrics` → Prometheus-текст со счётчиком `proxy_requests_total`
- `POST /v1/chat/completions` → проксирование на upstream по тому же пути

Ключевые механики:
- Тело запроса и заголовок `Authorization` передаются upstream без изменений.
- SSE-стрим (`stream: true`) пересылается немедленно, без буферизации (задержка на событие — единицы мс).
- При закрытии клиентом соединения посреди стрима соединение с upstream немедленно закрывается (reqwest-ответ дропается вместе с телом axum).
- Failover до первого байта клиенту: 5xx/429, ошибка подключения или таймаут первого SSE-события (TTFT_TIMEOUT_MS) → повтор на следующем upstream. Зависшая попытка отменяется.
- Если все upstream отказали — 502/503 с JSON-телом `{"error": {"message": ..., "type": ...}}`.
- После первого байта retry запрещён; обрыв стрима upstream завершает клиентский стрим без зависания.
- Выдерживает 200 одновременных стримов без потерь.

## Итерации проверки

Понадобилась 1 итерация сборки/проверки (после исправления ошибки компиляции о перемещении `resp` — заголовки извлекаются до потребления тела).

## Проблемы

- Ошибка компиляции `E0382` (borrow of moved value): `resp.bytes_stream()`/`resp.bytes()` перемещают `reqwest::Response`, поэтому заголовки копировались в `Response::builder()` до потребления тела.
- Запуск `check.py` с относительным путём `target/release/proxy.exe` падал с `FileNotFoundError` на Windows — потребовался абсолютный путь.
